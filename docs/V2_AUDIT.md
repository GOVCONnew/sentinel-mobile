# SENTINEL Mobile — v1 audit & baseline (STEP 0)

Written before the v2 changes, from reading the v1 code (`git show 9e2b4e4`) and measuring it. Numbers are from headless Chrome on the build box
(SwiftShader software WebGL, 8 vCPU): **use them only for relative comparisons**, not as iPhone latencies.

## 1 · What v1 actually ran

| Area | v1 behaviour (as implemented) |
|---|---|
| Detector | COCO-SSD 2.2.3 `lite_mobilenet_v2` (default) or `mobilenet_v2`, TF.js 4.22 WebGL → WASM → CPU fallback, model from `storage.googleapis.com/tfjs-models` |
| Input | Video frame drawn to a canvas with long side **320 px** (aspect kept), then the graph resizes internally to **300×300 — stretched, no letterbox** (a 16:9 frame is squashed 1.78×) |
| Thresholds | One global `minScore` slider (default **0.5**) for every class; class checklist filter |
| NMS | Inside COCO-SSD: `tf.image.nonMaxSuppression(boxes, maxScores, maxNumBoxes=20, iouThreshold=minScore, scoreThreshold=minScore)` — **IoU threshold is tied to the score threshold** (at 0.3 two people overlapping at IoU 0.31 are merged) and NMS is **class-agnostic** over each box's max class score. A person and the dog he walks can suppress each other. |
| Post-processing | COCO-SSD switches the global TF backend `webgl → cpu → webgl` on every frame for NMS and uses blocking `dataSync()` |
| Tracking | IoU + centroid matcher, a "new track" event after **2 hits**; no motion prediction, no low-score association; one 0.5-score frame pair was enough to log an event |
| Motion | 80×60 grayscale frame differencing vs previous frame, per-pixel threshold from the sensitivity slider, event when ≥ **3 %** of (ROI) pixels changed, 10 s debounce. No camera-shake, lighting or foliage handling. ROI = one rectangle. |
| Audio | YAMNet (vendored TF.js graph) on 0.975 s windows every **750 ms**; event when one of the **top-3 labels** contains a watch-list term (substring) with score ≥ 0.3; no smoothing, no ambient model |
| Scheduling | Single rAF loop; when idle runs audio if 750 ms elapsed else detection back-to-back (`low power`: detection ≥ 1 s apart). Detection is the critical path. |
| Storage | Events in `localStorage` (cap 3000), snapshots in IndexedDB; no incidents, no search, no storage estimate |
| iOS | Wake lock + nosleep video; no handling of `visibilitychange` — **time spent in background was silently missing from the log** |

## 2 · Per-stage cost (v1, headless)

| Stage | p50 | Notes |
|---|---|---|
| Capture/draw to 320 px canvas | ≈ 1 ms | `drawImage` |
| Pre-process + inference + COCO-SSD post-process (lite) | **357 ms** (p95 483) | measured in `bench/` over 156 frames; mostly WebGL inference + GPU→CPU readback; backend switch each frame |
| same, `mobilenet_v2` | 916 ms (p95 1033) | |
| Motion (80×60 diff) | < 1 ms | |
| YAMNet window | 130–170 ms | from v1 `test/results.json` |
| Overlay draw | < 1 ms | |

Bottleneck: detector inference + synchronous readback. Because detection runs back-to-back, the effective detector rate in headless was ~2.6/s; audio inference competes for the same thread.

## 3 · Reproducible benchmark (built for this audit)

* `bench/eval/` — **82 Wikimedia Commons images** (CC0/PD/CC BY/CC BY-SA, see `bench/ATTRIBUTION.md`), image-level labels in `ground_truth.json`:
  17 with person (hikers on forest trails, distant/small people, backlit, fog, snow), 20 with animals (roe/white-tailed deer, wild boar, dog — mostly in woods; COCO has no deer class, so any COCO animal class counts), 16 vehicles (forest roads, logging trucks, forestry tractor, ATV, parking at woodland), 30 empty woodland/foliage frames incl. dusk/backlit. Tags `small`/`lowlight`/`hard` mark 17 difficult positives.
  Labels are presence per group (person / animal / vehicle) per image — **not boxes**: precision/recall are image-level.
  Paintings, engravings, stamps and sports photos returned by search were excluded by hand.
* `bench/negframes/` — 70 frames (2 fps) from three real wind-in-trees videos + 4 exposure variants. Used for FP/min.
  "Raw FP/min" = frames with any person/animal/vehicle detection per minute of video; "Confirmed FP/min" = alarms after a 2-of-3-frames persistence rule (10 s debounce).
* `bench/seq/` — 13 motion sequences, 160×120 @ 10 fps, 7–14 s: the three real foliage videos, synthetic **sway** (normal/strong), **sun flicker**, **light ramp**, **moving cloud shadow**, **camera shake** (random walk ±6 px), a combination, and **3 positives** with a walking person-sized patch composited (sway / shake+light / real foliage). Generated by `bench/gen_sequences.py`.
* `bench/clips/` — 12 audio clips (16 kHz): 5 negatives (wind, heavy rain, light rain, rain+wind, rain+thunder) and 7 positives (birdsong ×2, dog bark, chainsaw, footsteps+birds, cars passing ×2, gunshots).

Runners: `node bench/run_bench.js` (detectors in headless Chrome → `bench/results/raw_*.json`), `node bench/score.js`, `node bench/motion_bench.js`, `node bench/run_audio_dump.js` + `node bench/audio_bench.js`, `node bench/report.js` (markdown tables).

## 4 · Baseline (v1) results

| Metric | v1 value |
|---|---|
| Person precision / recall (image-level) | 100 % / **59 %** |
| Animal precision / recall | 100 % / 65 % |
| Vehicle precision / recall | 100 % / 88 % |
| Overall F1 | 82 % |
| Recall on hard subset (small / low-light) | **36 %** |
| Detector FP/min on wind-blown foliage (raw / confirmed) | 0.0 / 0.0 (lite) · 3.2 / 1.7 (mnv2) |
| Detector latency p50 / p95 (headless) | 357 / 483 ms |
| Motion false alerts on negative sequences | **7 in 133 s = 3.2 /min** (strong sway, sun flicker, shake, real foliage all trigger) |
| Motion intruder detected | 1 / 3 (and that one only because the sequence was firing constantly) |
| Audio watch-list FP on wind/rain | **8 in 98 s = 4.9 /min** (wind & rain → "Vehicle", thunder → "Dog") |
| Audio positives hit | 6 / 7 (chainsaw clip is classified as insect/buzz by YAMNet) |

Conclusions that drove v2: v1's misses are recall problems on small/dark subjects (COCO-SSD at a stretched 300² input), its motion alerts are almost all foliage/shake/lighting, and its audio alerts in weather are dominated by YAMNet's wind/rain → vehicle confusion.
